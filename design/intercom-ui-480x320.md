# AI 对讲客户端界面（480×320 横屏）

状态：3.5B 固件已实现并完成实机联调，按当前 `custom_lcd_display.cc` 与 `Intercom` 核对，更新日期 2026-10-25。本文描述当前界面和已验证的交互行为。

## 1. 布局

目标板为 Waveshare ESP32-S3 Touch LCD 3.5B。横屏左侧约180px用于控制和小智回复，右侧约300px用于当前会话对讲记录。

```text
┌──────────────────┬──────────────────────────────┐
│ 设备：002         │ 对讲记录                     │
│                  │                              │
│ 对讲状态          │ 003 · 时长 · 识别文字        │
│ 房间：默认房间    │                              │
│ 开始对讲          │ 我 · 时长 · 识别文字         │
│                  │                              │
│   [ 开始对讲 ]    │ 系统：设备上线／房间邀请     │
│                  │                              │
│ 小智回复          │ 可滚动，点击记录回放         │
└──────────────────┴──────────────────────────────┘
```

左上角显示配置的本机对讲设备ID（例如“设备：002”），保留设备ID原有格式；未配置时显示“设备：未配置”。长ID在固定区域内省略显示，避免挤占房间信息。已删除“设备状态”和“Wi-Fi · 小智”固定标签。当前没有电池百分比、在线成员数、波形或独立录音计时展示。房间名称和对讲状态随 Intercom 更新。实时发言期间，左侧状态显示“说话中：设备ID”：本机录制显示本机ID，远端播放显示服务端start中的source_id，保留设备ID原有格式；播放排空或退出接收状态后恢复普通状态，不将记录回放标为实时发言。

## 2. 大按钮

按钮约145×82px，通过 LV_EVENT_CLICKED 调度应用任务执行 `Intercom::Press()`。普通模式点击一次开始实时采集和发送，再次点击结束；没有按住／松开逻辑，也没有独立 X 取消按钮。

| 状态 | 当前文案或行为 |
| --- | --- |
| 未配置／断线／连接中 | 对讲未配置／对讲未连接／对讲连接中，禁用 |
| 空闲可发言 | 开始对讲，点击开始 |
| 助手或音频忙 | 助手忙／音频播放中，禁用 |
| 录制中 | 说话中，再次点击结束 |
| 收尾中 | 发送中，等待完成 |
| 接收实时语音 | 说话中，禁用本机录音 |
| 记录回放中 | 语音回放中；当前触摸主按钮禁用，点击正在播放的记录可停止 |
| 托管模式 | 托管模式，点击请求退出，服务端确认后恢复普通模式 |

普通模式按钮蓝色（#3187C8），托管模式黄色（#E6B83D），当前不按录制／接收状态切换红绿配色。按钮文案优先显示托管模式。录制上限30秒、500帧及512KiB，先达到限制即结束。

### 接收缓冲溢出后的状态恢复

接收抖动缓冲最多保留12帧。缓冲满时，固件标记当前接收会话已溢出、丢弃缓冲及该段后续音频，并调度解码器重置；保留当前 message_id，以便匹配后续 end／abort。收到结束消息后清理会话标识及溢出标志，等待播放队列排空，再恢复可用状态，避免持续显示“说话中”。结束消息未到达时，沿用已有接收超时保护。

这是异常会话的收尾修复，溢出后的音频不补播，也没有解决网络突发收包或播放速度不足的根因。正常结束、断线、缺失end超时以及随后新对讲的恢复均需实机回归。

## 3. 房间和助手交互

房间创建、查询、加入、退出和接受邀请通过灵矽／小智语音 MCP 完成，屏幕没有房间表单或加入码输入框。调用self.intercom.list_rooms成功后，3.5B会弹出选房窗口，显示房间名称及其后的加入码（例如“调度组（加入码：1234）”），默认房间仅显示名称，当前房间用绿色底色标记。标题显示15秒倒计时，右上角X可手动关闭；超时保持原房间。点击普通房间以加入码申请加入，默认房间发送leave_room；等待确认期间禁用列表，显示最多5秒的确认等待。确认成功关闭，失败显示提示并重新开始15秒选择倒计时；确认超时关闭并提示重新查询，避免继续使用旧房间快照。断线或房间视图改变关闭弹窗；本机发言、接收或回放时提示对讲忙。关闭弹窗不会撤销已经发送的切房请求。按名称加入可先查询可加入房间，重名时应追问。修改类工具的 true 仅表示请求发送或排队，业务结果由对讲服务端确认，不能提前宣称成功。

小智回复显示在左侧按钮下方，右侧不显示用户与小智问答字幕。BOOT 键保留助手操作。非例外 MCP 调用后，小智 TTS 结束且扬声器排空时关闭助手音频会话，对讲连接保持在线。

## 4. 当前会话记录

图片记录显示发送者和“收到一张图片”，下面显示可点击的 JPEG 缩略图。点击缩略图或图片记录可打开大图弹窗；弹窗右上角 `X` 关闭并返回对讲界面。图片下载和解码在后台任务执行，失败时应提示图片加载失败。

右侧使用可滚动的彩色文字按钮，显示发送者、时长和 ASR 摘要。pending 显示识别占位；识别失败或禁用时仍可在音频有效期间回放。系统通知有独立底色，自动回复标记托管回复。

| 记录类型 | 底色 |
| --- | --- |
| 本机发言 | 浅绿色 #CDEAD9 |
| 远端发言 | 浅蓝色 #DFEAF5 |
| 系统通知 | 浅米色 #EEE2C9 |
| 正在回放 | 浅橙色 #FFD690 |

单击整条记录播放，再次单击停止。最多20条（含系统事件），空列表显示“暂无对讲记录”。用户接近底部时新内容跟随滚动，向上查看旧记录时保留位置。切房、断线清空，不查询历史；仅改房间名称不重置聊天视图。

回放由独立 HTTP 任务解析 AIR1 包流并逐包交给有界解码队列，不整段加载。实时对讲可以抢占回放；助手或本机录音忙时不能并发回放。音频失效返回410并提示“语音已过期”。上线、加入和邀请通知可在 TTS 完成且音频空闲时自动播放，待播队列最多4条。

## 5. 线程与验证

LVGL 回调只复制消息ID并投递应用任务，不执行网络、编码或阻塞等待。记录更新遵守显示锁，重建按钮释放旧事件数据；回放取消使用代次标记避免迟到任务向新会话继续投递音频。

3.5B 编译、刷机和实机联调已完成，已验证中文界面、触摸与滚动、连续录放音、实时抢占、托管开关、切房／断线取消等交互。长时间内存稳定性仍作为持续运行观察项。协议和资源限制见[对讲协议](intercom-protocol.md)与[会话记录设计](intercom-asr-session-chat.md)。
