# AIRadio 比赛产品方案与场景验收

本文面向三天赛制，说明产品设计依据和可现场复现的任务。当前没有客户访谈或客户试点结果；场景为产品假设，内部演示用于验证功能闭环，不能替代用户需求验证。

## 1. 首要场景与产品定位

优先展示有可用 IP 网络的仓库临时协作：负责人组织一个临时装卸小组，成员用对讲沟通任务，漏听后找回信息，忙碌时启用在线 AI 应答辅助。

选择仓库是因为组队、切组、任务口头同步可以组成连续演示，当前能力能够覆盖这些动作；尚未获得客户证据证明仓库是最佳市场。园区、物业和车队属于后续验证方向。

| 角色假设 | 关心的问题 | 对应产品设计 |
|---|---|---|
| 一线作业人员 | 立即说话、少操作、找回漏听内容 | 大按钮、语音操作、近期记录与回放 |
| 现场负责人 | 临时组织成员、回顾近期任务 | 房间与邀请、保留内容总结 |
| 采购与运营方 | 部署费用、使用效果、持续维护 | 终端与服务组合、配置控制台、成本核算 |
| 集成商 | 如何接入硬件和 AI 服务 | 开源固件、独立 Go 服务、协议与配置入口 |

## 2. 题目到产品的映射

| 比赛要求 | 当前实现 | 验收方式 |
|---|---|---|
| 通过灵活方式建群 | 房间创建、邀请与语音 MCP 操作 | 两台设备最终显示同一房间，后台成员一致 |
| 群内语音对讲 | 独立 WebSocket、Opus、半双工 | 接收设备实际播放发送设备的语音 |
| 语音切换群／房间 | 自然语言 MCP 查询、加入；查询后可触屏确认 | 以服务端确认和设备房间变化判断成功 |
| 合理的产品逻辑 | 即时发言用按钮，复杂操作用语音，状态可确认 | 按下面连续任务演示 |
| 延伸价值 | 转写、回放、总结、在线托管 | 分别核对真实结果，明确记录和业务边界 |

## 3. 一条贯穿演示的任务

演示前准备两台目标实机；实机不足时明确标注哪端使用浏览器模拟器。使用虚构任务，不展示真实客户数据。

1. **组织协作空间**：负责人创建房间，另一成员收到邀请后说“接受刚才的邀请”。确认两端房间及后台成员一致。
2. **立即沟通**：负责人用大按钮发送“把三号托盘送到二号装卸口，完成后回复”。另一端实际收听并回复。该句仅为演示输入，识别结果以实测为准。
3. **找回漏听信息**：等待异步转写后查看文字，点击原音回放，核对“托盘编号”和“装卸口编号”。
4. **梳理沟通**：说“总结刚才的对讲”。核对是否覆盖当前保留文字中的事实，不要求模型逐字输出固定答案。
5. **忙碌时辅助应答**：开启托管并确认黄色状态；另一端明确呼叫该设备，观察是否按上下文简短回应。模型可以选择不答，不将业务执行承诺设为通过条件。
6. **真人接管和切组**：若有自动语音播放，真人开始发言以验证抢占；退出托管，再查询并切换房间，确认状态更新及旧记录清理。

当前没有 WMS、库存查询、工单执行和外部业务工具。演示中的搬运任务由真人承担，AI 不代表任务已完成。

## 4. 交互取舍与失败恢复

| 情况 | 设计与观察点 | 当前边界 |
|---|---|---|
| 急需发言 | 大按钮立即发起对讲，不等待模型理解 | 点击开始、再次点击结束，不是按住说话 |
| 房间名或语音意图不清楚 | 查询实际房间列表，触屏选择并确认 | 语音与菜单哪种更快尚未比较验证 |
| 加入或托管请求已发送 | 等服务端确认后观察最终状态 | 工具返回排队成功不等于操作成功 |
| 别人在发言 | 观察忙碌反馈，结束后重试 | 当前全局发言锁也会阻塞其他房间 |
| ASR 错误或尚未完成 | 核对原音，必要时真人重新确认 | 不把文字视为业务指令的唯一依据 |
| 总结缺内容 | 核对记录范围与识别状态 | 最多 20 条设备记录，包含系统消息 |
| 托管不答或答非所问 | 真人接管、退出托管并记录输入输出 | 无业务工具、长期记忆或离线代答 |
| 切房或断线 | 观察旧会话、记录和托管清理 | 网络恢复不等于恢复之前的托管状态 |

## 5. 内部验收记录

以下为待执行方案，本文没有填入尚未采集的结果。每项建议重复三次，完整记录失败；三次仅用于演示准备，不构成可靠性统计。

| 项目 | 观察标准 | 需保留的材料 |
|---|---|---|
| 创建／接受邀请／切组 | 两端与服务端最终房间一致 | 指令、响应、状态截图 |
| 真人对讲 | 可听清任务，结束后恢复可用状态 | 两端视频、会话 ID、网络条件 |
| 转写与回放 | 编号等关键字段可核对，原音能回放 | 输入原音、识别文字、错误标记 |
| 总结 | 与保留文字一致，无新增任务事实 | 实际记录、总结输出、遗漏与错误 |
| 托管与接管 | 观察按需应答、真人抢占、退出后旧结果不播报 | 模式事件、输入输出、时间顺序 |
| 连续使用与重连 | 下一轮仍可发言，断线清理符合预期 | 固件日志、服务端日志、复现步骤 |

记录格式：日期／版本／设备与模型／网络／步骤／预期／实际／通过或失败／材料路径。计时时说明起止点；界面响应时间不等于端到端音频延迟。

## 6. 比赛期间与赛后的验证分工

三天内可以完成产品流程走查、内部任务演示、接口测试、成本假设和技术证据整理。无法据此证明客户付费意愿、生产效率提升或长期稳定性。

赛后优先验证：目标岗位是否频繁切组、转写是否减少重复询问、噪声环境下的识别与操作效果、托管是否有足够有用且可控的回答。若托管价值弱，优先打磨即时对讲与信息回顾，不强行扩大 AI 的参与范围。
