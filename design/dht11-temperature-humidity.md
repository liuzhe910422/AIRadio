# DHT11 本地温湿度采集与显示

状态：2026-10-31，按当前 3.5B 板级驱动和界面实现整理。ESP-IDF v6.0.2 编译通过；用户提供的实机日志与照片已确认能够读出温湿度并显示在标题栏。最后一次统一字体的固件已编译，尚未收到刷入后的照片；持续采样成功率和异常恢复仍需实机验证。

## 1. 目标与范围

在 Waveshare ESP32-S3 Touch LCD 3.5B 上接入一个 DHT11，约每5秒读取一次温湿度，同时输出串口日志，并显示在右侧“对讲记录”标题后。保留摄像头、屏幕、触摸和音频原有引脚。

当前能力属于设备本地监测：读数保存在 RAM 中，不上传对讲服务端，不写入聊天记录或 NVS，不增加 MCP 工具、协议字段、告警推送或历史曲线。不需要等待 Wi-Fi 或对讲服务连接成功才开始采集。

## 2. 接线与引脚约束

| DHT11 模块 | J8 PinOut | 说明 |
| --- | --- | --- |
| DATA / S / OUT | 第11脚，ESP_MOSI / GPIO10 | 固件使用 `GPIO_NUM_10` |
| VCC / ＋ | 第31或32脚，3.3V | 模块应支持3.3V供电 |
| GND / － | 第29或30脚，GND | 与开发板共地 |

GPIO10 与 SD 卡 MOSI 共用，因此必须取出 SD 卡，不能同时初始化 SD 卡功能。当前板级实现没有初始化 SD 卡；屏幕 QSPI 使用另一组 GPIO。物理脚号与 GPIO 编号不同，插接方向以板上1脚标记和丝印为准。

若模块没有自带上拉，在 DATA 与3.3V之间增加4.7kΩ～10kΩ电阻，资料推荐短线约5kΩ。驱动启用内部上拉，但它不能代替对外部上拉和线材质量的确认。不要让 DATA 被模块上拉至5V。可在传感器电源附近加100nF去耦电容，并远离屏幕和处理器等热源。

原理图还将 GPIO17 用作摄像头 VSYNC；本方案保留摄像头，未使用该引脚。GPIO43 属于串口控制台，GPIO44 用作音频 MCLK，也未改动。

## 3. 驱动与采集任务

实现位于 `main/boards/waveshare/esp32-s3-touch-lcd-3.5b/`：

| 文件或接口 | 职责 |
| --- | --- |
| `dht11_monitor.cc` / `.h` | 单线通信、脉冲解码、采集任务、最新读数快照 |
| `StartDht11Monitor(gpio_num_t)` | 板级启动一个板生命周期的监测任务 |
| `GetDht11Reading()` | 返回互斥锁保护的最新读数副本 |
| `waveshare-s3-touch-lcd-3.5b.cc` | 初始化显示和摄像头后，以 GPIO10 启动采集 |
| `custom_lcd_display.cc` / `.h` | 创建固定标题栏标签，刷新读数及异常状态 |
| `main/CMakeLists.txt` | 仅为此板增加 `esp_driver_rmt` 依赖 |

任务优先级为1，栈大小4096字节。任务启动后先等待至少1秒，每次读取结束后再等待至少5秒，因此实际两次读取开始的间隔略大于5秒，并非严格对齐的5秒定时器。失败也遵守同一间隔，不立即重试或补采。

单次通信流程：

1. 将 DATA 以开漏方式拉低超过18ms；实现使用约20ms以上的任务延时。
2. 先启动 RMT 接收，再释放 DATA，避免漏掉传感器的快速响应。
3. RMT 以1MHz分辨率记录脉冲，固定接收缓冲为64个符号；电平持续1ms时结束接收，任务等待上限约100ms。
4. 查找约80µs低电平与80µs高电平响应，解析40bit，高位先出。
5. 将前4字节之和的低8位与第5字节校验和比较，成功后才解析并发布数值。

驱动不长时间关闭中断，不在主事件循环或音频任务内轮询引脚。RMT 回调只记录符号数并释放信号量；解码和日志由采集任务执行。

资料描述旧版 DHT11 的小数字节为零。当前实现也兼容小数字节为0～9的模块，按十分位解析；不合法的小数字节、湿度大于100%或温度大于50°C会被拒绝。显示一位小数不代表传感器拥有0.1°C精度；资料给出的典型测温精度为±2°C、测湿精度为±5%RH。

## 4. 日志与错误处理

成功日志示例：

```text
I (...) DHT11: temperature=24.8 C, humidity=59.0 %RH
```

无响应、接收超时、帧不完整、脉冲异常、校验失败或数据异常均作为可恢复错误处理，不把失败当作零读数发布。资源初始化失败会打印错误并结束监测任务；传感器读取失败则继续下一个周期。

| 日志 | 含义或排查方向 |
| --- | --- |
| `Read failed: ESP_ERR_NOT_FOUND` | 未找到响应脉冲，检查供电、接线和上拉 |
| `Read failed: ESP_ERR_TIMEOUT` | 接收未在等待期限内完成 |
| `Read failed: ESP_ERR_INVALID_SIZE` | 响应之后不足40bit |
| `Invalid bit ...` 与 `ESP_ERR_INVALID_RESPONSE` | 包含异常位序、低/高电平宽度及电平，检查时序和信号质量 |
| `Read failed: ESP_ERR_INVALID_CRC` | 5字节校验和不匹配，当次数据丢弃 |
| `Invalid data: raw=...` 与 `ESP_ERR_INVALID_RESPONSE` | 校验通过但数值或小数字节格式超出当前支持范围 |

早期实现曾将所有非零小数字节判错，后续已兼容十分位数据。用户早期日志显示多数 `ESP_ERR_INVALID_RESPONSE`、少量成功读数；仅凭这些日志不能证明所有错误均由小数字节引起，仍需通过新版具体诊断判断。

## 5. 界面与线程边界

温湿度标签固定在右侧300px面板的顶部、标题右侧，不进入聊天列表，也不随聊天滚动。中文显示 `对讲记录` 和 `温湿度：24.8°C / 59.0%`，英文显示 `History` 和 `Temp/RH: 24.8°C / 59.0%`。

最终实现让标签继承界面正文字体及中文备用字体，与标题字号一致、顶部对齐。之前直接指定的小字体不含“温、湿”等汉字，导致只显示“度”；增加备用字体后又出现汉字大小不一致，现已移除独立小字体。数值文本先用标准 `snprintf` 格式化，再传给 LVGL，因为当前 LVGL 内置格式化器未启用浮点支持。

采集任务只在成功时更新互斥锁保护的 `Dht11Reading`，包括温度、湿度、最后成功时间和有效标志。现有应用每秒调用显示层刷新，显示层取得快照后在 LVGL 锁内更新标签，不跨任务直接操作控件。

| 状态 | 显示行为 |
| --- | --- |
| 首次成功读取前 | `温湿度：--°C / --%` |
| 成功读取 | 显示最新温湿度，保留一位小数 |
| 偶发失败 | 保留最近成功值 |
| 距最后成功已达15秒，或界面启动15秒仍无成功读数 | 显示“温湿度：读取异常”，文字为棕橙色；英文为 `Temp/RH: read error` |
| 异常后重新读取成功 | 自动恢复正常颜色及最新读数 |

时间判断使用单调时钟，不依赖网络校时。标签跟随现有对讲内存语言切换，不新增语言持久化配置。

## 6. 验证记录与待验证项

本次开发已完成 ESP-IDF v6.0.2 下当前3.5B配置编译和应用分区检查。最后一次统一字体版本应用分区约剩33%。临时主机测试覆盖脉冲解码、整数/十分位读数、校验失败、短帧、无响应、非法脉宽和非法数据；测试不能代替电气与真实时序验证。

此前运行的130项主机测试中，5项因仓库缺少 `.github/workflows/build.yml` 报错，3项跳过，其余通过；此记录来自驱动开发阶段，并非本次文档编辑重新运行的结果。

用户实机日志确认摄像头初始化成功、DHT11能读出数据；后续照片确认温湿度已出现在对讲记录标题栏。照片也暴露了缺字及混合字号问题。最后统一字体版本尚待刷机确认。

后续实机应检查：连续运行时的采样成功率；中英文、占位符和异常文案是否完整；传感器断开超过15秒后的提示及重连恢复；聊天滚动、切房和语言切换；拍照、录音、播放、Wi-Fi重连期间的采样和音频稳定性。传感器应远离板上热源，避免将板卡自热误判为环境温度变化。
